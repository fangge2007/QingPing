# 清屏：权限、限制与实际方案

版本：0.4.1；核对日期：2026-10-23。此处区分公开 API 可以做的事情、应用当前实现的事情，以及需要设备实测的事情。本版本未在安卓模拟器或真机执行验收。

0.4.1 增加面向不同 APP 和安卓手机的离线使用教程，可在用途同意前、保护首页、应用页及设置打开，支持搜索与展开。教程展示当前运行条件，并提供前往现有设置的入口；阅读与搜索不会授予权限、开启保护、修改规则或启用模拟点击。本次不改广告识别算法、权限声明及用途同意版本 4。

## 先理解边界

普通 Android 应用不能取得“截获所有其他 APP 的 startActivity 请求并批准或拒绝”的通用权限。清屏选择公开无障碍 API：观察窗口、读取符合权限范围的控件，并执行用户预先配置的点击或返回动作。因此，本实现的“拦截”分为跳过广告和跳转后返回，不能承诺目标 APP 从未打开，也不能使已发生的请求或交易自动撤销。这是本实现根据公开交互 API 范围作出的边界判断。

## 权限和设置

华为、vivo 的部分系统另有逐 APP 设备方向权限控制，可由用户手动限制摇一摇；这是厂商系统能力，普通清屏 APK 不能代为更改。入口、版本条件和来源见 [系统防摇一摇指南](VENDOR_SENSOR_GUIDE.md)。系统拒绝访问的次数不会计入清屏统计。

| 项目 | 是否需要 | 用途与限制 |
| --- | --- | --- |
| 无障碍服务授权 | 核心功能需要，用户手动开启 | 接收窗口事件、识别可读控件，执行控件点击和全局返回。清屏不能自行开启。界面中需先展示数据访问用途并取得主动同意。 |
| `BIND_ACCESSIBILITY_SERVICE` | 服务组件声明 | 用作服务的绑定保护，只有系统可绑定；不是弹窗申请的普通权限。 |
| `canRetrieveWindowContent` | 服务能力声明 | 读取无障碍节点。实际可见数据受系统、目标 APP、工作资料隔离、敏感内容限制及节点暴露方式影响。 |
| `canPerformGestures` | 服务能力声明 | 让已授权的无障碍服务发送手势。逐 APP 模拟点击默认关闭，精确规则另需 `allowGesture=true`；只在已匹配的小型控件点击失败或受理但确认超时后尝试中心点，不盲点屏幕。升级后若系统没有加载能力，需关闭再开启一次服务。 |
| `RECEIVE_BOOT_COMPLETED` | 已声明，普通权限 | 接收系统开机完成广播，用于恢复检查提示；不能据此强行打开无障碍或保证服务重新连接。首次安装后需先打开应用。 |
| `POST_NOTIFICATIONS` | 可选，Android 13+ 手动授予 | 显示用户选择的开机/恢复提示。拒绝通知不会让已连接的无障碍服务停止。 |
| 电池设置、厂商自启动设置 | 可选，用户手动调整 | 本项目打开系统设置供用户选择；没有直接申请电池优化豁免。厂商菜单和效果不同，均不能保证永久运行。 |
| 启动器应用可见性 `<queries>` | 已限定声明 | 发现具有桌面入口的 APP，供用户选择；不是 `QUERY_ALL_PACKAGES`。不保证列出工作资料、私密空间、双开或没有桌面入口的全部包。 |

Android 的 [无障碍服务文档](https://developer.android.com/guide/topics/ui/accessibility/service) 描述了服务注册、控件访问和动作能力。Android 13+ 的 [通知运行时权限](https://developer.android.com/develop/ui/views/notifications/notification-permission) 与无障碍授权彼此独立。应用发现范围遵循 [包可见性声明](https://developer.android.com/training/package-visibility/declaring)。

本项目不申请 `INTERNET`、`SYSTEM_ALERT_WINDOW`、`PACKAGE_USAGE_STATS`、`QUERY_ALL_PACKAGES`、媒体投影、Root、设备管理器、精确闹钟或通知读取权限。不实现本地 VPN，不解密 HTTPS，也不读取其他 APP 的私有文件。

侧载安装的应用在 Android 13+ 上可能无法立即启用无障碍。应先阅读源码和用途，再由用户按系统提示决定是否允许受限设置。具体入口见 [Android 官方说明](https://support.google.com/android/answer/12623953?hl=en)；清屏不尝试绕过这项保护。

## 可实际运行的处理流程

1. 用户阅读说明、主动同意，手动打开无障碍，启用全局保护及指定 APP。当前保持用途同意版本 4，披露系统允许的更多节点及超时后的模拟点击后备。已完成版本 4 同意的用户从 0.4.0 覆盖升级到 0.4.1 无需再次同意；更早版本的同意不能直接启用当前保护，按软件提示重新阅读。使用原签名覆盖安装保留原设置、规则和统计。
2. 服务配置包含公开的 flagIncludeNotImportantViews，仅请求系统允许暴露的更多节点，不能强行获得系统或目标 APP 未公开的内容；不伪造 isAccessibilityTool 用途，不使用 Shizuku/隐藏 API。屏幕解锁且所选 APP 在前台时，服务响应窗口、内容及点击事件；进入后的密集检测窗口默认 15 秒，每约 250 毫秒主动重扫，之后每约 1.5 秒继续低频检查。锁屏、屏幕关闭、暂停保护或离开已选 APP 后停止对应扫描。每次常规遍历最多 700 节点、24 层，另先做最多 8 个已核实/已配置 ID 的直接查询，每个最多接入 8 个结果；查询结果必须检查完整祖先路径，不能越过输入子树、窗口、来源或深度限制。输入框及其子树不读取。低频轮询有助于发现没有新事件的后续控件，但仍可能漏过短暂页面；它可能增加耗电，实际影响需真机测量，不承诺永久后台或固定识别时延。
3. 裸“跳过”“Skip”“跳过 5”等普通标签，只在进入前 15 秒且有独立广告上下文时，检查上下边缘的小型可见、可用控件。倒计时本身不证明广告。15 秒后只处理明确广告关闭/跳过语义、已核实 SDK 控件、来源隔离开屏目录及符合范围的精确规则。来源目录要求完整来源与完整 ID、短跳过语义、小型边缘区域；B站两版进入前 15 秒另允许已核实 ID 的空标签后备，不额外要求可读广告徽标；B站两版支持同 APP 后期开屏，其余新增目录限进入后 30 秒。明确“关闭广告”“关闭此条广告”“跳过视频广告”等小型控件可位于中央；2–5 个直接短叶子文字可在小型可点击父节点中合并核对，合并的普通“跳过”仍限前 15 秒与独立广告证据；通用“关闭”仍不足以自动执行。下载、安装、支付、购买、领取等奖励或业务动作，以及含有这些动作的混合父节点会被拒绝，即使精确规则指向它们也不执行。
4. 优先请求 `ACTION_CLICK`。只有显式匹配的控件、逐 APP 模拟点击开关和合适尺寸都满足时才可在点击失败后尝试中心手势，精确规则还需单独允许。普通点击受理后 2.5 秒仍未确认时，只有原窗口、原位置的同一明确候选才可在既有手势授权下升级；手势前还检查任意尺寸的危险点击祖先。disabled 或“若干秒后关闭”等等待状态不发送动作。每段广告最多接受 4 次关闭点击，阶段按钮共享预算；同一控件最多先试两次，第二次后至少等待 10 秒才允许最后一次延迟尝试。同控件拒绝请求最多 3 次，每轮含拒绝的总请求最多 8 次，持续无效时不无限重试。
5. 请求接受后仍需观察界面：在最后一次接受动作后的 2.5 秒内，同一来源两次完整节点扫描均无广告上下文、所有匹配关闭/跳过控件均消失，首次至少等待 200 毫秒、两次至少相隔 180 毫秒，才累计一次跳过。阶段按钮更换、disabled 节点、读取不完整、请求失败及确认超时不计成功。只有完整普通内容经过至少间隔 500 毫秒的两次观测，才恢复下一段广告的动作预算；清屏成功后仍可处理同一 APP 再次出现的广告。
6. 用户为来源 APP 配置一个明确目标包后，只有同时具备广告上下文，以及运动触发标签或已核实的三个开屏 ID，才短时准备跳转返回；证据有效期 2 秒，静态横幅广告标记不会单独触发。切到配置目标包时才请求一次系统返回，请求成功后 2.5 秒内回到来源包才计跳转返回。此功能无法可靠判断人的意图，故必须逐 APP 启用并实测，尤其需要验证正常业务跳转得到保留。
7. 设置、统计及用户主动保存的精确规则写入本地应用私有存储；不自动记录屏幕正文，也不上传。规则可通过本地 JSON 导入预览后按 key 合并/导出，不兼容 GKD 语法，不联网订阅。

## 精确关闭规则与手动诊断

入口为“APP → 对应 APP → 精确关闭规则与诊断”。一条规则的所有非空条件必须同时按原文匹配；没有 viewId 时必须指定完整 Activity，不能把任意页面的通用“关闭”直接当广告按钮。规则格式为 `qingping-rules-v1`，最多 100 条、256KB。导入只保存规则，不自动打开 APP 保护或模拟点击。

时间范围由每条规则决定：`persistent` 缺省或 false 时保留原进入后窗口，`windowSeconds` 可设 3–30 秒、默认 15 秒，同一 APP 切页或收到新事件不会重置它。旧单 ID 设置仍只在进入前 15 秒执行。手动添加时可单独勾选“持续匹配”，或在导入 JSON 中设 `persistent=true`，用于 APP 前台持续处理已核实的弹窗/视频关闭控件；导入预览及规则列表会显示范围，导出保留该字段。持续匹配扩大的是时间范围，不能绕过来源、页面、尺寸、可用状态与危险动作排除条件。旧规则不会因升级或后台低频扫描而自动扩大作用时间。

用户主动开始的诊断持续 30 秒，仅针对选定 APP。诊断排除密码、可编辑控件和输入子树，只保存最多 20 个候选按钮的资源 ID、短标签、短描述及 Activity 等匹配信息；不保存整树、页面正文或截图。候选短时保存在内存，2 分钟后失效。只有用户核实并点击保存时，选中的条件才持久化为精确规则；候选不代表必然是广告关闭按钮。

原有开屏资源名为 `tt_splash_skip_btn`、`ksad_splash_circle_skip_view` 和 `ksad_skip_view_skip`。0.3.0 新增五个有条件候选：`tt_reward_full_count_down_after_close`、`ksad_auto_close_btn`、`jad_feed_close`、`ms_activity_sdk_interstitial_cacel`、`anythink_myoffer_btn_close_id`。新增 ID 不能自己提供广告上下文；字节、美数、Anythink 三项还严格匹配已核实的完整 SDK Activity，具体条件和 MIT 来源见 [SDK 源码分析](SDK_RESEARCH_0.3.md)。不能把任意相似 `close` 名称或 SDK 前缀作为白名单，也不据此宣称整类 SDK 已通过验证。

匹配后仍检查来源 APP 已启用、规则时间范围、当前前台包和可交互窗口、控件可见性/尺寸及动作权限，不越过上层业务弹窗点击底层广告。图标关闭或不支持 ACTION_CLICK 的控件可按 [fixture 样例](../examples/fixture-close-rule.json) 验证双重手势授权。规则变化、页面遮挡或布局更新仍可能造成误操作，因此应逐 APP 验证。

节点选择与返回确认是启发式判断。目标 APP 可以改变资源 ID、布局、无障碍语义或导航结构；广告自动消失和用户主动操作也可能影响观测。统计应理解为“确认到界面结果的规则执行量”，不能当作对广告 SDK 的审计。

## 哪些可以实现

| 功能 | 实现程度 |
| --- | --- |
| 有可读“跳过”控件的常见开屏广告 | 条件满足时自动点击；需要逐 APP 验证 |
| 已适配的图标关闭、仅触摸可操作控件 | 精确规则匹配并满足双重模拟点击授权时可尝试手势；不保证不可读画面 |
| 延迟出现的关闭控件、应用内弹窗 | 解锁且所选 APP 前台时持续事件检查与低频重扫；晚于 15 秒的普通裸跳过仍不执行，需明确广告语义、已核实 SDK 或相应精确规则 |
| 倒计时后才可关闭的视频 | 等待可访问控件出现且变为可用，不加速播放、不绕过强制观看；没有可用关闭控件时无法关闭 |
| 两阶段及再次出现的广告 | 同段共用动作预算，最终界面消失才确认；稳定普通内容后恢复处理后续段落，需要设备实测 |
| 本地规则导入/导出和手动按钮诊断 | 已实现，不订阅联网规则、不自动启用新 APP |
| 按来源 APP 统计并在清屏查看 | 已实现本地累计，区分跳过和跳转返回 |
| 设置 APP 规则、暂停/关闭保护 | 已实现 |
| 指定广告来源 → 目标 APP 的跳转返回 | 已实现条件式事后返回，不是启动前阻断 |
| 重启后尝试继续 | 系统重新绑定已启用无障碍时可恢复；提供开机提示和设置引导 |
| 清除最近任务后继续 | 在系统仍保留/重新绑定服务时可工作，不能跨厂商保证 |

## 哪些不能保证或当前不实现

| 情形 | 原因或结果 |
| --- | --- |
| 100% 广告识别和零误触 | 没有统一广告接口，无法完全区分业务页面与广告；规则必须维护 |
| 无障碍节点未暴露的 Canvas、游戏、视频画面或受保护内容 | 本项目不截图识别、不注入目标进程、不盲点坐标 |
| 在目标 APP 打开之前拦截所有 Intent/deep link | 普通应用没有通用的系统级启动防火墙权限 |
| 拦截摇一摇传感器本身 | 无 Root 华为/vivo 上无法用普通无障碍关闭其他 APP 的传感器监听；可尝试先关闭广告页，或在符合规则的外部跳转后返回。AdClose 等进程 Hook 不可直接搬入普通 APK，见 [源码研究](SENSOR_RESEARCH.md) |
| 覆盖广告画面、防下载、防网络请求 | 本项目不是系统防火墙或网络过滤器 |
| 同 APP 内所有广告导航、任意浏览器页面 | 当前规则限定来源包 → 目标包，不做通用业务页面撤回 |
| 用户强行停止后自行复活 | 停止状态由系统维护；用户再次启动或交互后才可能解除 |
| 永久后台、静默自启、自动开启无障碍 | Android 和厂商可停止进程、撤销服务连接或限制广播；权限必须由用户授予 |
| 锁屏或尚未首次解锁时保护 | 锁屏停止扫描和动作；当前不实现 Direct Boot 服务，按解锁后使用设计 |
| 以当前拦截广告用途上架 Google Play | Play 政策明确将阻止或干扰其他 APP 展示广告列为违规示例，不应据此规划 Play 分发 |

Android 15 的 [应用停止状态说明](https://developer.android.com/about/versions/15/behavior-changes-all#enhanced-stop-states) 明确保留用户强行停止的意图。普通最近任务划除和“强行停止”不是同一个动作，但厂商“一键清理”可能附加更激进的限制，需逐设备测试。

## 为什么没有“前台服务保活”

无障碍服务由系统管理和绑定，不需要另起空转服务来完成节点处理。增加通知、`START_STICKY`、定时任务或 `BOOT_COMPLETED` 并不等于永久存活；误用前台服务类型也会造成兼容和分发问题。本项目仅使用真实的无障碍连接及明确的用户提示。

Android 12+ 限制 [从后台启动前台服务](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)，新的 Android 版本还对开机启动特定类型增加限制。[Doze 和待机文档](https://developer.android.com/training/monitoring-device-state/doze-standby) 也说明后台工作会被系统调度。无需承诺不可验证的“强保活”即可实现本项目的核心交互。

## 隐私和分发

无障碍拥有很高的数据访问能力。0.4.2 默认只接收清屏自身事件，启用后按所选来源与明确跳转目标设置系统事件包名过滤；停用或撤销同意后收窄。包名过滤控制事件交付，不限制读屏 API 本身，因此仍在读取根节点后及动作前检查实际前台、系统关键包名、授权及锁屏状态。仅在屏幕解锁且所选 APP 位于前台时持续遍历其节点并执行规则。密码、可编辑控件与输入子树不读取文字或继续遍历。普通匹配短暂使用非输入控件文字和资源 ID，不持久化屏幕正文。

危险节点自身不作广告证据或动作候选，但含下载说明等聚合描述的父节点不会因此剪掉整个子树，仍可检查独立安全的子控件。小型危险可点击父节点会抑制后代动作，模拟点击还会检查任意尺寸的危险点击祖先。节点读取失败、数量或深度达到上限、来源等校验失败会使扫描不完整；存在待确认动作时跳过输入子树也会阻止完整确认，不能把未读区域当作广告已经消失。

手动诊断仅保留短时按钮候选；用户主动保存时才将选中按钮的 ID、短标签、描述和 Activity 等持久化为精确规则。持久数据还包括 APP 设置、计数与时间，不包括完整节点树和截图。用户可暂停、撤销同意、关闭系统服务或卸载。

清屏不是以辅助残障人士为主要目的的产品，不应声明 `isAccessibilityTool=true`。需要准确披露访问的数据及用途并取得明确同意，见 [Google Play 无障碍 API 政策](https://support.google.com/googleplay/android-developer/answer/10964491?hl=en)。此外，[设备与网络滥用政策](https://support.google.com/googleplay/android-developer/answer/16559646?hl=en) 明确将阻止或干扰其他 APP 展示广告列为违规示例。这是当前用途的实质分发限制，不能仅靠改名称或无障碍申报解决；本交付以本地安装调试版本为范围，不应承诺 Google Play 上架。
