# 清屏 0.4.1

清屏是一个面向无 Root 安卓设备的原型应用：对手动选定的 APP 识别开屏、应用内弹窗及视频中的可访问广告关闭控件，并在满足指定规则时对广告引起的跨 APP 跳转执行返回。支持在应用内按来源 APP 查看跳过和跳转返回统计。

**跳转返回发生在目标 APP 已打开之后；普通应用没有通用的系统级 Intent 防火墙权限。本项目不承诺全部广告可拦截，也不承诺永不被系统停止。** 权限和限制请先阅读 [说明](PERMISSIONS_AND_LIMITS.md)。

应用内已加入完整的“使用教程与问题处理”，可在用途同意前、保护首页、应用页和设置打开，支持离线搜索和按主题展开。教程按操作步骤和问题现象组织，适用于不同 APP 与能够运行 Android APK 的手机，不设单一 APP 或品牌的专项教程。系统菜单以本机为准，教程范围不等于所有机型和广告均已验证。

## 已实现的范围

- 原生 Android 界面；Android 8.0（API 26）及以上，编译和目标 API 36。
- 内置通用教程：首次启用、覆盖升级、应用选择与隔离空间、按钮不响应、倒计时、延迟或连续广告、视频、摇一摇、后台恢复、诊断、精确规则、导入导出、统计、误触处理及隐私。教程可查看当前运行条件，并提供手动前往无障碍、应用配置和后台设置的入口；阅读不会授予权限或更改规则。
- 首次使用展示无障碍数据访问说明，由用户主动同意，再到系统页面手动开启服务。0.4.1 保持用途同意版本 4；已完成版本 4 同意的用户覆盖升级无需再次同意，从更早版本升级则按软件显示的用途说明重新确认。使用原签名覆盖安装保留原设置、规则和统计。
- 全局保护开关与逐 APP 规则；默认不对任何 APP 执行动作。
- 通过公开服务配置读取系统允许的更多无障碍节点；优先按已核实 ID 查询，仍检查完整祖先路径的输入隔离、来源包和窗口。
- 保留哔哩哔哩/HD、知乎、中国电信、TeraBox、华为视频、大麦、UC 的来源隔离开屏目录：完整 ID 加短跳过语义及小型边缘控件（B站两版进入前 15 秒另支持空标签），不再额外要求可读“广告”徽标。B站支持同一 APP 内返回首页后才出现的开屏，其余目录限进入后 30 秒。详见 [历史 B站核对](BILIBILI_RESEARCH_0.4.md) 与 [目录来源](SPLASH_CATALOG_RESEARCH.md)。
- 屏幕解锁且所选 APP 在前台时持续响应界面事件。进入后的密集检测窗口默认 15 秒，每约 250 毫秒重扫；之后每约 1.5 秒低频检查后续广告，锁屏或离开所选 APP 后停止该 APP 的轮询。每次最多扫描 700 节点、24 层，排除输入子树。持续检测可能增加耗电，实际耗电及不同系统的后台效果仍需真机评估。
- 裸“跳过”“Skip”“跳过 5”等普通文案仅在进入前 15 秒、上下边缘的小型可用控件及独立广告上下文同时满足时处理；倒计时本身不再充当广告证据。此后仍可识别“关闭广告”“关闭此条广告”“跳过视频广告”等明确文案，包括居中的小型弹窗控件。对拆成 2–5 个短叶子文字的小型可点击容器，也可合并核对明确关闭语义；普通合并“跳过”仍限前 15 秒及独立广告证据。通用“关闭”不会自动点击；下载、安装、支付等危险动作及混合父节点会被拒绝；带聚合下载说明的大容器继续扫描其独立子按钮，避免把整个广告树剪掉。
- 保留 `tt_splash_skip_btn`、`ksad_splash_circle_skip_view`、`ksad_skip_view_skip` 三个已核实开屏资源名；新增字节、快手、JAD、美数、Anythink 的五个有条件关闭 ID。新增 ID 本身不提供广告证据，三个还需匹配完整 SDK Activity。来源与约束详见 [SDK 源码分析](SDK_RESEARCH_0.3.md)；适配资源名不代表真实 APP 或 SDK 全家族已验证。
- 支持按包名、Activity、完整控件 ID、精确短文案或无障碍描述配置关闭规则。原精确规则默认保留进入后 3–30 秒窗口（默认 15 秒），同 APP 切页或新事件不会重置。手动添加或导入可单独设 `persistent=true`，用于 APP 前台持续匹配；默认 false，导入预览会显示范围。旧单 ID 设置仍限进入前 15 秒。支持本地 JSON 导入预览、按 key 合并和导出，不兼容 GKD 语法、不联网订阅。
- 逐 APP 的“模拟点击”默认关闭。只有已匹配的精确规则、内置来源或已知 SDK 控件、合适尺寸和逐 APP 授权都满足时才尝试中心手势；精确规则还需 `allowGesture=true`。普通点击失败可后备，点击受理但 2.5 秒未确认时也可升级；超时升级必须仍为相同窗口及位置，手势前检查危险点击祖先。
- 手动启动 30 秒按钮诊断，排除输入框及其子树，仅暂存最多 20 个候选控件的 ID、短标签、描述及 Activity；结果只在内存短时可用，2 分钟后失效。用户选择并保存后才成为本地精确规则。
- 对用户配置的来源包 → 单一明确目标包组合，仅在近期同时有广告上下文，以及运动触发标签或上述三个开屏 ID 时执行一次返回；证据有效期 2 秒。静态横幅的“广告”标记不会单独触发返回，正常业务主动打开目标 APP 应保留。
- 只把同一来源两次完整观测中广告上下文及所有匹配关闭控件消失的结果计为跳过；候选识别、请求接受和阶段按钮更换不算成功。连续阶段共用最多 4 次接受的关闭点击；同一控件最多两次较快尝试，第二次后至少等 10 秒才允许最后一次延迟尝试。拒绝请求同控件最多 3 次，每轮含拒绝的总请求最多 8 次，避免失败后持续尝试。普通内容经至少间隔 500 毫秒的两次完整观测后，恢复处理后续广告，可分别统计关闭后再次出现的广告。按来源 APP 区分跳过与跳转返回。
- 提供系统无障碍、通知、电池设置入口与开机恢复提示。重启后的服务连接由 Android 管理。
- 无联网权限；无 Root、截图、悬浮窗、VPN、使用情况访问、全量应用列表或自启守护进程。

## 构建

环境：JDK 17、Android SDK Platform 36、AGP 8.10.1、Gradle 8.11.1。构建依赖下载需要网络，安装后的应用不联网。

在 Android Studio 打开此目录，安装缺失的 SDK 后同步。也可以在项目目录运行：

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :fixture:assembleDebug :fixturetarget:assembleDebug
```

Windows 下也可使用 `scripts/setup-toolchain.ps1` 在项目 `.tools` 目录准备便携工具，再运行 `scripts/verify.ps1` 完成构建、单元测试及 Lint。脚本不修改系统 PATH。Android SDK 条款与许可提示仍按正常流程处理。

主要输出：

| 文件 | 用途 |
| --- | --- |
| `qingping-0.4.1-debug.apk` | 本次交付的清屏调试安装包 |
| `qingping-0.4.1-source.zip` | 本次交付的源码包 |
| `app/build/outputs/apk/debug/app-debug.apk` | 清屏，可安装调试包 |
| `fixture/build/outputs/apk/debug/fixture-debug.apk` | 可重复的测试广告 APP |
| `fixturetarget/build/outputs/apk/debug/fixturetarget-debug.apk` | 测试广告跳转的目标 APP |

调试包适合本机试用。正式分发应自行保管签名密钥、使用 release 签名配置并完成设备验证。

## 安装和启用

1. 安装清屏 APK，打开应用并阅读无障碍披露说明，主动同意；同意前也能先看教程。使用原签名覆盖升级，不要先卸载或清数据。已完成用途同意版本 4 的用户本次无需重新同意；更早版本按软件提示操作。升级后若系统开关已开启但服务未连接，可在系统中关闭再打开一次“清屏”无障碍服务。
2. 在系统无障碍设置中打开“清屏”。Android 13 及以上侧载安装可能出现“受限设置”；仅在信任源码和安装包时，按照系统“应用信息 → 更多 → 允许受限设置”提示处理。不同系统入口可能不同。
3. 打开清屏保护，选择要处理的 APP，逐一启用规则。不要一次开启全部应用。
4. 处理不了的图标关闭，可进入“APP → 对应 APP → 精确关闭规则与诊断”，手动添加规则，或启动 30 秒诊断后到目标 APP 展示广告，再回来刷新结果。核实候选用途后再保存；用于较晚出现的弹窗或视频时，可单独勾选“持续匹配”，确认该条件不会命中普通业务控件。需要手势时，另打开该 APP 的模拟点击开关并允许该条规则模拟点击。
5. 可在设置中导入/导出 `qingping-rules-v1` JSON。导入先预览，再按 key 合并，同 key 的新规则覆盖旧规则；导入不会自动开启 APP 保护或模拟点击。随附 [图标关闭样例](../examples/fixture-close-rule.json) 仅供 fixture 验证。
6. 有跳转问题的 APP，可按界面配置一个明确的目标包。先验证正常页面主动打开目标 APP 不会被退回。该功能不能关闭摇一摇传感器。
7. 如需开机提醒，允许通知并打开相应选项。经常断连时，按本机提供的入口检查后台/自启动、电池限制或最近任务锁定；这些设置仍不能保证永久运行。
8. 先用随附的两个测试 APP 验证；再试自己日常使用的 APP。详见 [设备测试计划](DEVICE_TEST_PLAN.md)。

## 在应用内查教程

打开“使用教程与问题处理”，可搜索“点不动”“倒计时”“后台”“误触”等关键词，或展开主题逐步阅读。顶部运行条件卡区分用途同意、服务实际连接、保护总开关与已选 APP 数量；点击设置入口后仍需用户手动操作。

遇到所有 APP 都失效，先查运行状态和后台限制；只有某个按钮失效，再做 30 秒诊断、核实精确规则，必要时按双重授权要求使用模拟点击。晚到弹窗核对规则时间范围，误触则先暂停再收窄规则。可见但没有可读控件、尚未允许关闭或没有跳过功能的广告，不能靠放宽规则强行处理。

如系统提供逐 APP 的设备方向或动作权限，可按本机说明评估限制摇一摇；该系统能力需手动调整，清屏不能自动修改，也无法读取系统拦截次数。历史厂商入口参考保留在 [系统防摇一摇指南](VENDOR_SENSOR_GUIDE.md)，不代表全部版本均有相同菜单。

## 规则和统计的含义

“跳过”包括经确认的无障碍控件点击或用户允许的控件中心手势，不是删除广告，也不阻止广告网络请求。“跳转返回”是全局返回动作，不会撤销目标 APP 已发生的启动、网络请求或其他副作用。普通 APK 没有通用的权限来禁用其他 APP 的运动传感器；详见 [GitHub 传感器源码研究](SENSOR_RESEARCH.md)。

规则按包名隔离；用户可以关闭某 APP、暂停保护、撤销同意或在系统中关闭无障碍。精确资源 ID 属于 APP 特定规则，目标 APP 升级后可能失效。建议只填写已经确认用途的跳过控件 ID；`persistent=true` 会扩大该条规则的时间范围，需核实其页面条件。

统计表示规则执行后观察到的界面结果，不是广告平台的网络级拦截量。其他 APP 的界面不可见、读取失败、请求失败或确认超时都可能使统计少于实际跳过次数。即使界面变化符合规则，也无法用公开 API 证明广告 SDK 内部业务状态。

设置、统计和用户主动保存的精确规则保存在清屏的应用私有目录。自动匹配不保存整棵节点树、页面正文或截图；手动诊断的候选只短时保存在内存，只有主动保存规则时才持久化选中的按钮条件。卸载或清除应用数据会删除这些内容；本项目关闭 Android 备份。

## 验证状态

0.4.1 的构建、单元测试、Lint 和签名结果以本次交付的 [验证报告](VERIFICATION.md) 为准；旧版本的验证结果不能代替新版本结果。原签名用于覆盖安装并保留数据；签名核对结果也见该报告。版本变更见 [0.4.1 交付说明](RELEASE_0.4.1.md)。

本版本未在安卓模拟器或真机执行验收，未测量真实 APP 覆盖率、耗电或各系统后台恢复表现。现有测试 APP 场景包括 35 秒后弹窗、8 秒禁用倒计时、连续两阶段、关闭后再次展示，以及业务控件与多窗口误触负例；可按 [设备测试计划](DEVICE_TEST_PLAN.md) 复现。历史 GitHub 研究见 [GITHUB_RESEARCH.md](GITHUB_RESEARCH.md)、[SDK_RESEARCH_0.3.md](SDK_RESEARCH_0.3.md)、[PROJECT_COMPARISON.md](PROJECT_COMPARISON.md) 及 [VISUAL_DETECTION_RESEARCH.md](VISUAL_DETECTION_RESEARCH.md)。0.4.1 的教程更新不改变广告识别算法。
