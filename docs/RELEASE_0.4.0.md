# 清屏 0.4.0：可见跳过按钮的兼容性修复

本轮针对用户报告的“华为上 B 站和其它 APP 看得到跳过，却无法关闭”，继续按安卓公开能力实现，未加入针对单一手机型号的分支。最低 Android 8.0；不同 ROM 的节点暴露、手势及后台行为仍需各自验收，不能从构建通过推断所有品牌型号都有效。

## 这次具体修了什么

1. 请求系统包括未标记为重要的无障碍视图，并在服务连接时同步配置。GKD 与开屏跳过都使用这项公开配置；它不等于 Root、隐藏 API 或强行取得不公开的节点。
2. 为 B 站 `count_down/skip`、HD 及另外六个 APP 的已核实开屏 ID 加来源隔离目录。目录要求完整来源、完整 ID、短跳过语义及小型边缘区域，不再要求广告标识必须能读成文字；不是给任意 APP 的 `skip` 全局放行。只有B站两版的已核实 ID 在进入前 15 秒允许空文字/描述的受限后备，仍要求可见、可用、小型边缘控件与安全点击路径；其它来源或有非跳过业务文案时不采用空标签后备。
3. 先对内置/已配置 ID 做有上限的直接查询，再遍历树，减少大页面先耗尽遍历预算的漏检；查询结果必须经过完整祖先路径的输入、来源和窗口校验。
4. 含下载、打开或超长聚合描述的大容器继续遍历子节点，不再连独立安全关闭按钮一起漏掉。危险节点本身、危险小可点击父节点及其后代动作仍被拒绝。
5. 逐 APP 允许模拟点击后，明确控件的 `ACTION_CLICK` 虽受理、但 2.5 秒内未确认关闭时，可在下一次受限请求中尝试手势；要求仍为原窗口和原位置，且没有危险点击祖先。没有打开模拟点击就不会自动开启。
6. 支持“跳过 | 5”“跳过｜5s”等倒计时分隔符，仍排除跳过片头、登录、教程、下载等业务语义。

源码依据见 [B站实际规则与执行器](BILIBILI_RESEARCH_0.4.md)、[开屏目录](SPLASH_CATALOG_RESEARCH.md)。保留来源统计、稳定清屏确认、连续广告预算、原签名和后台恢复指南；不把请求受理或自然倒计时结束直接当成功。

## 用户安装时的操作

1. 覆盖安装本版，不要先卸载或清数据，以保留统计与配置。
2. 打开清屏，重新同意版本 4 的节点读取及手势后备用途；确认保护和所需 APP 已启用。
3. 到系统无障碍设置，把清屏关闭再打开一次，让系统重新载入节点配置。
4. 若仍是按钮看得到却点不动，在对应 APP 规则中打开“允许模拟点击”。B站内置规则不需要手填资源 ID；自定义精确规则还需该条 `allowGesture=true`。

## 验证边界

构建、测试和签名结果见 [验证记录](VERIFICATION.md)。本轮未获得用户的 B站节点或连接其手机，没有真机复现，不能宣称这就是其唯一根因或已在其手机修好。针对图片里根本没有暴露可访问控件的情况，本版没有 OCR/截图，也不会盲点坐标、点击广告正文或退出整个 APP 伪装成功。

测试 APP 增加聚合危险描述、危险父节点和非重要视图等对照场景，步骤见 [设备测试计划](DEVICE_TEST_PLAN.md)。这些本地控件测试不能代替真实 SDK、跨 ROM 恢复、耗电和误触率测量。
