# 设备测试计划与历史场景

状态：这是可执行的设备验收计划，不代表已经完成真机验证。构建、单元测试、模拟器和真机结果应分别记录。

当前执行请使用[真机验收记录模板](DEVICE_ACCEPTANCE_TEMPLATE.md)，逐项填写设备/应用版本、结果和证据。下文保留 0.3/0.4 阶段场景说明；0.4.2 调试/正式签名不同，先核对[迁移与构建说明](RELEASE_BUILD.md)。自动化入口见[验证工具](VERIFICATION_TOOLING.md)。

## 准备

构建三个模块后安装：

```powershell
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r fixture/build/outputs/apk/debug/fixture-debug.apk
adb install -r fixturetarget/build/outputs/apk/debug/fixturetarget-debug.apk
```

打开清屏，阅读并同意当前版本的无障碍披露，手动启用服务及全局保护。在 APP 列表中只启用“清屏测试广告”（`cn.qingping.fixture`）。一般文案规则测试时保持精确资源 ID 为空、移除该 APP 的自定义精确规则，并保持 APP 模拟点击关闭；精确规则和手势是另外一组测试。覆盖升级后按清屏提示重新确认用途；如果服务能力未加载，在系统中关闭再打开一次清屏无障碍服务。

每次测试前记录两个计数。测试 APP 的桌面入口现为测试菜单，可直接点击场景名称，不必逐次执行 ADB。0.3.0 在解锁且选定 APP 前台时持续响应事件：进入窗口内约 250 毫秒，随后约 1.5 秒重扫。每树及每个广告轮次的动作有上限；成功后经过至少两次、跨度 500 毫秒的完整普通内容观测才恢复下一轮。不要靠切包重置掩盖连续广告问题。若需要清理历史测试 Activity，通过返回关闭再重新启动，或仅强停 **fixture**。不要强停清屏来准备普通用例。

```powershell
adb shell input keyevent KEYCODE_HOME
adb shell am force-stop cn.qingping.fixture
adb shell am start -n cn.qingping.fixture/.SplashActivity --es mode skip
```

## 功能验收

0.4.0 升级后先重新同意版本 4 用途，关闭再打开系统无障碍以载入包含非重要节点的配置。B站无需手工填写控件 ID；要测试超时手势后备，需在该 APP 明确打开模拟点击，自定义规则还需规则单独允许。

真实 APP 验收应包括哔哩哔哩冷启动、切回、视频/小组件返回首页后才出现的开屏及连续两段：有可读短跳过语义和已核实完整 ID 时，即使额外广告徽标不可读也应进入候选；正常播放的“跳过片头”、搜索、登录和下载入口不可自动操作。当前没有在真实 B站执行这些步骤，不能预填通过。目录里其它 APP 分别记录实际版本、按钮暴露及结果，不把一个版本外推到全部品牌。

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 默认关闭 | 新装清屏，不同意/不选 APP，打开测试广告 | 不自动点击；不增加统计 |
| 标准开屏 | 选中测试来源，打开 `--es mode skip` | 点击右上“跳过广告 5”，进入内容页；来源跳过 +1 |
| 连续事件 | 保留内容页等待，再切至清屏查看 | 同一广告不会不断加计数 |
| 普通跳过 | 打开 `--es mode normal`，精确 ID 为空 | 页面保留，不点击跳过，不加计数 |
| 3 秒延迟 | 打开 `--es mode delayed` | 3 秒后出现的广告仍在窗口内，可跳过 |
| 10 秒延迟 | 打开 `--es mode late`，保持默认规则 | 10 秒后出现的广告仍在 15 秒窗口内，可跳过并确认一次 |
| 18 秒延迟 | 打开 `--es mode toolate`，没有延长窗口的精确规则 | 18 秒后明确“跳过广告 5”可由事件或低频重扫处理；裸“跳过 5”在 15 秒后不可仅靠同页广告标识放行 |
| 指定目标返回 | 来源规则目标设置 `cn.qingping.fixturetarget`，打开 `--es mode jump` 后尽快点击“点击查看广告详情” | 目标短暂打开后返回来源；来源跳转返回 +1，目标不记来源统计 |
| 普通主动跳转 | 打开 `--es mode normaljump` 后点“主动打开目标 APP” | 留在目标 APP，不自动返回，不加计数 |
| 未配置目标 | 清空目标包后打开 jump，点详情 | 留在目标 APP |
| 静止广告 | 打开 jump，广告保持可见，3 秒后再点详情 | 页面有明确运动触发说明，服务刷新短时返回证据，返回一次；普通静态横幅不应启用返回 |
| 真实摇一摇 | 打开 `--es mode shake`，选择关闭该 APP 的自动跳过但保留指定目标返回，再摇动设备或点“模拟摇一摇跳转” | fixture 自己可触发目标启动；符合返回规则时目标打开后退回，不能宣称已阻断传感器 |
| 临时放行 | 设置中允许跳转 10 分钟后打开 jump，点详情 | 留在目标 APP；结束放行后可重新测试返回 |
| 来源未选中 | 关闭测试来源规则后重试 | 不执行自动动作 |
| 精确 ID | 设置 `cn.qingping.fixture:id/skip_button` 后重试 skip | 规则匹配该控件；测试后清空，以免影响普通跳过用例 |
| 配错 ID | 设置不存在的 ID，观察实际界面规则说明 | 不发生盲点屏幕或点击全屏容器 |
| 暂停保护 | 暂停后打开广告和跳转 | 不自动操作；恢复后可再次测试 |
| 撤销同意 | 使用应用提供的撤销入口后重试 | 停止自动操作，需再次主动授权流程 |
| 重开清屏 | 执行成功后关闭界面再打开 | 已保存统计保留 |
| 清理统计 | 执行清理并重新打开应用 | 统计清零；新事件从零累计 |

跳转的广告上下文只短时有效，需要近期仍可见的广告证据、运动触发说明或已知开屏 SDK 控件，以及明确配置的目标包；不能只靠很久以前的广告证据返回。普通内容的主动打开目标 APP 必须保留。动作请求成功但后续界面不可读取或确认失败时，不应虚增成功统计。

## 0.3.0 延迟、视频、连续广告与多窗口回归

以下场景均可从测试菜单启动，也可将上面的 ADB 命令中 `--es mode skip` 替换为对应 mode。每项测试前后记录统计；测试进行中不要手动点击关闭按钮、按返回或切去清屏，等场景结束再查看统计。所有页面都是本地控件，不加载广告 SDK、不联网，也不播放真实视频；这些用例验证可访问控件与状态转换，不能证明真实视频 SDK 的覆盖率。

| mode / 菜单入口 | 可复现步骤 | 验收标准 |
| --- | --- | --- |
| `popup35` / 35 秒后显示应用内弹窗 | 点击后保持前台，等待倒计时从 35 到 0；不切换包或 Activity | 超过原 30 秒上限后，新弹窗事件仍可被处理；居中的“关闭广告”被点击后弹窗消失、下层普通内容保留，跳过 +1 |
| `video` / 视频倒计时 | 观察前 8 秒按钮禁用，再观察按钮文字变为“关闭广告”且启用 | 禁用期间不操作、不计数；启用后才能点击，进入结束内容页后跳过 +1；不得把等待倒计时等同为绕过视频限制 |
| `chain` / 连续两阶段广告 | 第一阶段按钮被点击后立刻显示第二阶段，广告证据始终存在；第二阶段使用不同 ID | 不能把第一阶段按钮消失直接计为成功；允许继续处理第二阶段的小型明确关闭控件，最终普通内容出现后合计跳过 +1 |
| `repeat` / 关闭后 4 秒再次展示 | 第一段关闭后，同一 Activity 展示普通内容 4 秒，再显示第二段，复用相同 `skip_button` ID | 第一段确认 +1；普通内容稳定观测后安全恢复检测，第二段也关闭，最终合计 +2；结束后继续等待 5 秒不能重复增加 |
| `dialog` / 独立窗口居中弹窗 | 启动后 0.5 秒显示居中 Dialog；上层有明确“关闭广告”，下层是普通内容 | 识别当前可交互窗口；只点击上层小型明确控件。关闭后普通内容保留，跳过 +1，不退出整个 APP |
| `split` / 拆分文字：跳 / 过 / 广告 | 右上 132dp × 52dp 可点击父容器本身无 text/description，只有 3 个直接、不可点击的 TextView 叶子“跳”“过”“广告”；页面另有独立“广告”标识。保持默认规则、精确 ID 为空、模拟点击关闭 | 合并同一小容器的直接文字并点击父容器；进入同一 `SplashActivity` 的普通内容页后跳过 +1，继续等待 5 秒不重复计数。不能靠配置精确 ID 或手势通过 |
| `splitbusiness` / 拆分业务按钮 | 与 split 相同的右上父容器和独立广告标识，直接叶子改为“跳过”“下载”；等待至少 10 秒，不手动点击 | 父容器和文字保留，业务按钮次数始终 0，清屏统计不变；不能只匹配“跳过”叶子而忽略同父容器的危险业务文字。该按钮仅更新计数，不下载、安装或跳转 |
| `business` / 普通业务与伪跳过 CTA | 等待至少 10 秒；向下滚动确认所有按钮及“业务按钮被点击次数”；不要自己点击这些按钮 | “关闭”“跳过”“跳过 5”“Skip 3”“跳过广告并下载”，以及 text 为“跳过广告”但 description 为“立即下载并安装”的按钮均保留；业务按钮次数始终 0、清屏统计不变。危险按钮不能为同页其他业务按钮制造广告上下文 |
| `businessdialog` / 普通业务弹窗覆盖底层广告 | 上层普通业务 Dialog 有“关闭”；底层广告仍可见。等待 10 秒，记录业务点击次数，再用系统返回手动结束此负例 | 保留普通业务窗口，不点击它的“关闭”，不越过上层窗口点击底层广告。手动结束负例前业务次数为 0，清屏统计不变；手动关闭之后底层广告恢复可交互不属于此断言范围 |

主要稳定 ID：`video_close`、`stage_one_skip`、`stage_two_close`、`dialog_close`、`skip_button`、`compound_control`、`compound_business_control`。它们的完整前缀为 `cn.qingping.fixture:id/`。默认规则回归时不要为这些节点添加精确规则，否则可能掩盖通用匹配问题。拆分场景应在屏幕宽度至少 275dp、高度至少 289dp 的竖屏设备上验收，确保 132dp × 52dp 父容器不超过屏幕宽度 48%、高度 18% 的动作边界；超小屏不匹配不能记为成功。业务按钮只更新页面上的点击次数和最近按钮名称，不会下载、安装、支付或跳转；出现非手动的次数变化即为误触，不能当成跳过成功。

`repeat` 与 `chain` 都保留同一 `SplashActivity`，避免把新 Activity 或切包误当作连续广告支持。`popup35` 等待时的文本每秒更新，最终 Dialog 也会产生窗口事件；此用例验证长期使用后有事件的新广告；低频重扫对静默插入仍提供检查，但不能保证系统暴露不可访问的隐藏控件。

## 聚合父节点与非重要节点回归

以下为新增待执行用例，未连接设备、未完成真机验证。保持测试来源已选择、保护已开、精确 ID 为空、自定义规则已清空、模拟点击关闭。所有正例使用明确“跳过广告”文案及独立“广告”叶子，不给生产内置规则添加 fixture 包名或控件 ID。两个聚合父描述变体共用 `aggregate` mode；测试菜单分别提供入口，也可用参数区分。

| mode / 菜单入口 | 可复现结构与操作 | 验收标准 |
| --- | --- | --- |
| `aggregate` / 父容器聚合“下载”描述 | `adb shell am start -n cn.qingping.fixture/.SplashActivity --es mode aggregate`；不可点击的页面 FrameLayout 有“立即下载”聚合 description，独立叶子显示“广告”，右上独立可点击 Button `aggregate_skip` 显示“跳过广告” | 危险父描述不能剪掉整个子树；只点击安全的独立子 Button，进入同一 Activity 普通内容页后跳过 +1。不能点击父容器或把父描述当成可执行广告证据 |
| `aggregate` + `--ez longDescription true` / 父容器超长描述 | 在上述命令末尾加 `--ez longDescription true`；父描述超过 160 字且不含下载等动作词，其他结构不变。菜单“父容器超长描述”自动传此参数 | 超长父描述本身不产生候选，也不阻止继续遍历安全子控件；独立子 Button 关闭后跳过 +1。继续等待 5 秒不重复计数 |
| `dangerousparent` / 危险可点父容器包含跳过叶子 | 右上 132dp × 52dp 可点击父容器 `dangerous_parent` 的 description 为“立即下载并安装”，其不可点击直接叶子 `dangerous_parent_skip_leaf` 显示“跳过广告”；另有独立“广告”标识。等待至少 10 秒，不手动点击 | 不能把安全叶子上溯到危险父容器执行动作；父容器及子文字保留，“危险父容器被点击次数”始终 0，清屏跳过统计不变。该监听器只计数，不下载、安装或跳转 |
| `notimportant` / 非重要原生跳过节点 | 右上原生 Button `unimportant_skip` 可点击、显示“跳过广告”，但设置 `importantForAccessibility=NO`。升级后在系统关闭再开启清屏服务，确认新配置已加载，再启动此页 | 在系统确实向清屏暴露该节点的前提下，包含 `flagIncludeNotImportantViews` 的服务应能读取并点击它，进入普通内容页后跳过 +1。若诊断中不出现该节点且页面保留，记录系统和节点可见性，不以 APK 构建成功宣称通过 |

上述 ID 前缀均为 `cn.qingping.fixture:id/`。沿用前述小屏几何边界；这些控件是原生 Android View，不模拟 WebView、Canvas 绘制按钮、`NO_HIDE_DESCENDANTS`、安全窗口或系统对其他节点的访问限制。`flagIncludeNotImportantViews` 只能请求系统返回未标为重要的节点，不能强制生成应用未提供的虚拟节点。建议华为、vivo 分别记录实际诊断节点、自动关闭结果、统计差值和是否重新绑定服务；本地 fixture 通过也不等于 B站或其他真实 APP 已验收。

## 精确规则、模拟点击与诊断

打开“APP → 清屏测试广告 → 精确关闭规则与诊断”，并在对应 APP 规则中控制模拟点击开关。测试使用的 Activity 为 `cn.qingping.fixture.SplashActivity`。

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 图标默认不操作 | 打开 `--es mode imageclose`，不导入规则、APP 模拟点击关闭 | 左上图标保留，不把通用关闭描述盲目变成动作，不增加成功统计 |
| 导入预览取消 | 在设置中选择 `examples/fixture-close-rule.json`，查看预览后取消 | 规则列表不变；不启用 APP 或模拟点击 |
| 导入按 key 合并 | 确认导入该文件，重复导入同一文件 | 同 key 规则替换，不重复增加；APP 保护和模拟点击状态不自动打开 |
| 只有规则允许 | 样例 `allowGesture=true`，APP 模拟点击仍关闭，再打开 imageclose | 图标 `clickable=false`，不发送手势，不计成功 |
| 只有 APP 允许 | APP 模拟点击打开，将样例规则 `allowGesture` 改为 false 再确认导入 | 不对该规则发送手势，不计成功 |
| 双重授权 | 导入原样例并打开 APP 模拟点击，重新打开 imageclose | 普通点击不可用时，尝试已匹配图标中心手势，内容页出现后仅确认 +1 |
| 点击接受却无效果：关闭手势 | 导入原样例，但关闭 APP 模拟点击；启动 `--es mode noopclick`，等待至少 12 秒，不手动点击 | `image_close` 是 description 为“关闭广告”的原生 Button；语义 ACTION_CLICK 只更新页面请求次数并保留按钮。不能因请求返回 true 就计成功，跳过统计不变；请求受每控件/每轮上限限制 |
| 点击接受却无效果：超时升级 | 导入原样例并打开 APP 模拟点击，重新启动 `--es mode noopclick`；不要手动触摸按钮、切 APP 或换窗口 | 至少一次语义请求接受但未关闭后，等待确认超时；仅当同包、同窗口、同位置的明确控件仍安全匹配时可升级手势。只有 Button 收到真实 ACTION_UP 才进入同一 Activity 的普通内容页；页面展示此前语义请求次数，最终跳过仅 +1。若按钮移动或换窗口，不得沿用旧身份直接升级 |
| 全屏危险点击祖先拒绝手势 | 原样例 `allowGesture=true` 且 APP 模拟点击开启，启动 `--es mode dangerousgesture`；等待至少 10 秒，不手动触摸页面 | 同一 `image_close` ID、同一“关闭广告”description 的不可点击图标置于全屏可点击父容器，父 description 为“立即下载并安装”。图标无触摸监听器，触摸本会交给危险父。即使双重授权也必须拒绝，危险父容器被点击次数始终 0、图标保留、统计不变。此监听器只计数，不下载、安装或跳转 |
| 精确条件不匹配 | 将样例 description 改为其他文字，或 Activity 改为其他完整类名再导入 | 不匹配该图标，不发送手势，不增加计数 |
| 自定义 30 秒窗口 | 为 `cn.qingping.fixture:id/skip_button`、上述 Activity 创建 30 秒精确规则，打开 toolate | 指定控件可在延长的有界主动扫描中处理；规则不扩大其他节点的匹配条件。普通裸跳过控件无精确规则时不会延长 15 秒匹配窗口；明确广告文案则可持续匹配 |
| 规则范围校验 | 尝试导入 windowSeconds=2/31、未知字段、重复 key、超限文件、GKD 订阅格式 | 明确拒绝，不部分静默导入；支持格式为 qingping-rules-v1、最多 100 条/256KB |
| 规则导出 | 导出后检查 JSON，再在设备上导入 | 条件和手势字段保留；导出不包含整树或截图 |
| 启动诊断 | 点“开始 30 秒按钮诊断”，30 秒内切到 imageclose，再回来点“刷新诊断结果” | 显示 Activity、扫描状态和按钮候选；最多 20 个，包含 image_close 及“关闭广告”描述时可选择 |
| 诊断不自动落盘 | 查看诊断后关闭，不保存任何候选，再重开应用 | 不自动新增精确规则；没有整树、正文或截图文件 |
| 诊断保存 | 对核实的 image_close 点“用此候选创建规则”，检查字段并保存 | 仅持久化确认后的规则；不自动启用 APP 保护或模拟点击 |
| 诊断到期 | 停止诊断并等待最近报告生成后超过 2 分钟再刷新 | 旧结果失效，不继续提供旧候选 |
| 输入与扫描边界 | 在专用测试界面加入输入框/密码框，以及超过 700 节点或 24 层的结构 | 不读取输入子树；超限显示不完整，不把不完整扫描当成功确认 |
| 请求未确认 | 用专用测试界面让目标控件接受点击但不消失 | 不计成功；同轮动作受次数限制。重复事件不能绕过次数限制，只有符合规则的稳定普通内容才可为后续广告恢复检测 |

`imageclose` 场景的测试图标完整 ID 为 `cn.qingping.fixture:id/image_close`；它有无障碍描述“关闭广告”，声明不可点击，仅处理真实触摸 ACTION_UP，专门验证精确规则的手势后备。切勿将此样例直接用于其他 APP。

`noopclick` 和 `dangerousgesture` 复用上述 ID 与 description 以验证同一份精确规则的动作安全性；前者为可点击 Button，后者为不可点击 ImageView。两场景均是新增待执行设备用例，不能以编译结果代替语义请求、触摸事件和统计的实际观测。每次重新启动场景以重置页面计数，测试前后记录清屏统计；完成后关闭测试 APP 手势并移除样例规则，再执行默认规则回归。

## 后台、重启和权限

| 场景 | 操作 | 应检查 |
| --- | --- | --- |
| 最近任务划除 | 从最近任务划掉清屏，再打开 fixture | 服务是否仍连接；不同 ROM 分别记录 |
| 系统一键清理 | 执行系统清理，再打开 fixture | 是否需手动重开清屏/无障碍；不可写永久保证 |
| 正常重启 | 首次启动过清屏且授权后重启，解锁后等待系统恢复，再测试 | 无障碍连接状态、开机提醒、保护是否实际执行 |
| 强行停止清屏 | 应用信息中强停清屏，再打开 fixture | 允许失效；应通过手动打开清屏并检查服务恢复，不承诺自复活 |
| 关闭无障碍 | 系统手动关闭后打开清屏 | UI 应显示实际状态，不宣称仍在保护 |
| 拒绝通知 | Android 13+ 拒绝通知权限 | 不发可见提醒，核心无障碍功能仍可用 |
| 侧载受限设置 | 新装 APK 后尝试开启无障碍 | 展示/说明系统限制；不绕过系统授权 |
| 电池受限/不受限 | 分别设置后测试待机、解锁、重开 | 记录差别，不宣称电池豁免消除强停限制 |
| 屏幕关闭后解锁 | 休眠后打开 fixture | 是否继续处理；无多次重复统计 |
| APP 升级 | 从旧版本保留数据覆盖安装 0.3.0，再尝试保护 | 设置、统计保留；按清屏当前提示重新确认用途。若服务能力未生效，关闭再打开一次系统无障碍后复测 |
